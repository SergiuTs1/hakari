# hakari

Особистий щоденник ваги та складу тіла. Мінімалістичний японський стиль,
офлайн, без акаунтів, без сервера. Дані живуть лише на твоєму пристрої.

Головна ідея: інструмент забирає **вісім секунд на день** і відповідає на
одне питання — *скільки з утраченої ваги це жир, а скільки м'язи*.

## Запуск локально

```bash
python -m http.server 8787 --directory .
```

Далі відкрий `http://localhost:8787`.

На `localhost` service worker навмисно не кешує — інакше правиш CSS,
оновлюєш сторінку й бачиш стару версію.

## Розгортання на GitHub Pages

PWA ставиться на iPhone тільки з HTTPS, тому потрібен справжній хостинг.

1. Створи порожній репозиторій `hakari` на GitHub.
2. З цієї папки:
   ```bash
   git remote add origin https://github.com/<твій-логін>/hakari.git
   git push -u origin main
   ```
3. Settings → Pages → Source: **Deploy from a branch**, гілка `main`, папка `/ (root)`.
4. За хвилину сайт буде на `https://<твій-логін>.github.io/hakari/`.

**Важливо:** щоразу, коли міняєш файли, піднось версію `CACHE` у
[`sw.js`](sw.js) (`hakari-v1` → `hakari-v2`). Інакше телефон
показуватиме стару версію з кешу.

## Встановлення на iPhone

1. Відкрий адресу сайту **в Safari** (не в Chrome — там встановлення не працює).
2. Поділитись → **На екран «Домів»**.
3. Запускай тільки з іконки на домашньому екрані.

Чому саме так: у режимі з домашнього екрана застосунок працює
повноекранно, без адресного рядка, і його локальні дані система
тримає надійніше, ніж дані звичайної вкладки Safari.

## Нагадування

PWA на iOS **не вміє** локальних запланованих сповіщень, а Web Push
потребує окремого push-сервера. Тому нагадування робимо нативно —
і виходить навіть надійніше за сповіщення.

**Команди (Shortcuts) → Автоматизація → Час доби**

| Коли | Дія |
|---|---|
| щодня, у твій час зважування | «Відкрити URL» → адреса застосунку |
| щонеділі 10:00 | «Відкрити URL» → те саме, для обмірів і бекапу |

Постав «Запускати одразу», без запиту на підтвердження, і вимкни
«Сповіщати про запуск» — інакше отримаєш банер, який змахнеш не
прокинувшись.

**Важливо: автоматизація — це сигнал, а не місце для вводу.** Дія
«Відкрити застосунок» на іконку з домашнього екрана не наводиться —
у списку застосунків Команд її немає. Лишається «Відкрити URL», а вона
відкриває Safari, де в застосунка **окреме сховище**, не те, що в
іконки. Введена у вкладці вага лягла б у паралельну базу, якої більше
ніколи не побачиш.

Тому у вкладці браузера застосунок ввід не показує взагалі: замість
нього стоїть екран «відкрий hakari з домашнього екрана». Вкладка
робить рівно одне — не дає про зважування забути; далі один тап по
іконці. Тримати іконку в Dock — ще менше тертя.

Запасний варіант: щоденне нагадування в застосунку «Нагадування».

## Бекап — не пропускай

Дані лежать в IndexedDB на пристрої. Safari з часом чистить локальні
сховища сайтів, якими давно не користувались; для застосунку з
домашнього екрана правила м'якші, але ставити на це піврічну історію
зважувань не варто.

Тому раз на тиждень: **«записи» → зберегти копію** → зберегти файл у
Files / iCloud Drive. Два тапи. Якщо копії давно не було, підпис під
кнопкою стає золотим.

Відновлення зливає дані, а не затирає: записи з файлу перекривають
однойменні дати, решта лишається на місці.

Фото прогресу («записи» → фото) лежать у тому самому файлі бекапу — окремого
експорту для них немає навмисно, щоб не було другого ритуалу, про
який легко забути.

## Як це рахується

**Тренд.** Експоненційне згладжування (Hacker's Diet), α = 0.1:

```
trend[i] = trend[i-1] + α · (weight[i] − trend[i-1])
```

Велика цифра на головному екрані — це **тренд**, а не сьогоднішня вага.
Сира вага стрибає на ±1 кг від солі, сну й води; показувати її як
головний результат — найшвидший спосіб втратити мотивацію. Тому після
збереження поле ваги стоїть порожнє, а поруч — «записано»: сирого числа
на екрані немає взагалі, воно за один тап по полю, якщо треба виправити
описку.

У день без зважування тренд просто не рухається. Саме тому можна
пропустити тиждень і повернутись, нічого не зламавши.

**Темп.** Лінійна регресія по тренду за останні 21 день, у кг/тиждень.

**Нагляд за швидкістю.** Втрата понад ~1% маси тіла на тиждень — зона,
де разом із жиром починає йти м'яз. Застосунок тихо про це скаже.

**Відсоток жиру.** Метод US Navy — по зросту, обхвату шиї й талії
(у жінок додається обхват стегон):

```
ч:  495 / (1.0324  − 0.19077·log₁₀(талія − шия)          + 0.15456·log₁₀(зріст)) − 450
ж:  495 / (1.29579 − 0.35004·log₁₀(талія + стегна − шия) + 0.22100·log₁₀(зріст)) − 450
```

Це **власна лінійка**, і саме в цьому сенс. Абсолютна похибка методу —
близько ±3–4%: якщо застосунок показує 20%, насправді може бути 17 або
23, і точну цифру дасть лише DEXA. Але похибка стабільна й зсуває
результат завжди в один бік. Тому порівнювати себе з собою минулого
місяця можна, а з чиїмось числом із інтернету — ні.

Найчутливіше місце — не талія сама по собі, а різниця *талія − шия*:
сантиметр помилки в будь-якій з двох дає близько 0.7% жиру. Шию тому
треба мірити так само дисципліновано, як талію. Обміри роблять раз на
тиждень, зранку натще, того самого дня тижня. Через 10 днів без обміру
цифра на головному екрані гасне — вона підстаріла, але не зникає.

**Підсумок перемикачів.** Під перемикачами на «сьогодні» стоїть рядок «за тиждень»:
скільки разів кожен натиснуто за останні 7 днів. Перемикачі й доти
писались у базу, але нічого не повертали, а дія без віддачі з часом
перестає здаватись вартою тапу. Знаменника немає навмисно — «5 з 7»
читалось би як недобір, хоча тижневої норми тут не існує. Чого не було,
того й не показано: нуль на головному екрані працює як докір, а не як
число. Нових полів це не додає, тому вісім секунд на день лишаються
вісьмома.

**Зважувань за весь час.** Рядок у «записи» під консистентністю: скільки
разів ти зважився від першого запису. Серії тут немає навмисно — це
число пропуск не зменшує, тому його нема як провалити. Стрік у день
пропуску забирає накопичене, і саме в той день застосунок закривають;
цей лічильник у той самий день просто не додає одиницю. Рахуються дні
саме зі зважуванням: тап по «білок» теж створює запис, і лічильник, що росте
від самого перемикача, швидко перестав би щось означати.

**Консистентність.** Частка заповнених днів за останні 30, ціль — 80%,
не 100%. Серій поспіль тут немає навмисно: стрік, який обнуляється, —
машина для провини й найкоротший шлях до того, щоб усе закинути.
Пропуски в календарі показані золотом (кінцугі), а не червоним.

Числом вона показується без відсотка й без знаменника — просто «14 днів».
«10% · 3 з 30» робило з рядка табель успішності: знаменник задає норму,
якої тут не існує. Ціль 80% лишається живою в енсо на «сьогодні», де чисел
немає взагалі.

**Чого в застосунку немає навмисно.** Цільової ваги й відліку «до цілі».
Це був єдиний показник, що вимірював борг, а не пройдене, — і при
рекомпозиції він може не зрушити місяцями, хоча жир іде. Питання, на яке
відповідає головний екран, — «я рухаюсь у правильний бік», а не «скільки
мені ще залишилось». Повертати без запиту не треба.
